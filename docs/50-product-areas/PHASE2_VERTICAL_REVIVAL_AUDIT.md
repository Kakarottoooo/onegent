## Safety Boundary

Phase 2 revival means proving old hotel/flight paths still work inside the
current runtime, not expanding automation authority.

Hard stops:

- Do not submit payment.
- Do not enter CVV.
- Do not bypass OTP, CAPTCHA, login, or provider account checks.
- Do not click final booking or purchase confirmation.
- Do not run live provider flows without explicit founder approval for the
  exact run.

### Expedia Flight

Status: closest to demo revival.

Known latest live evidence:

- The legacy-shape worker error was not present in the latest evidence.
- DB params were correct for MCO to BNA.
- The visible Southwest card existed in screenshots.
- Runtime failed at Expedia flight-card DOM scan.

Most likely remaining blockers:

- Flight inventory changed between search and click.
- Checkout traveler/payment page selectors may need fresh artifact evidence.

  early in that case.

  new selector work.

### Hotel Provider

Status: architecture exists and now has no-live artifact classification, but is
not demo-verified tonight.

Current path:

- Trip commit can create hotel steps.
- Start route can build Booking.com native date/adult search URLs.
- Booking.com provider has guest-details and payment-boundary detection.
- Hotels.com provider reuses Expedia Group guest/payment form helpers.

Most likely blockers:

- Booking.com selected-date / room-selection selectors may have drifted.
- Hotel profile/payment checks are strict and can fail before provider work if
  billing profile fields are incomplete.
- Provider login/bot/network walls need fresh artifacts before code changes.

  selector drift, guest-details reached, payment/manual review, login/CAPTCHA
  boundary, profile gating, network/provider failure, and safety-stop negative
  evidence.
- `docs/50-product-areas/HOTEL_CONTROLLED_RETRY_RUNBOOK.md` defines the future
  controlled retry evidence path.

Next controlled check:

- Do not start with a broad live run.
- First add or identify a no-live artifact fixture for one Booking.com hotel
  checkout boundary.
- Then run one approved hotel task only to safe handoff.

### Booking.com / Hotels.com

Status: provider modules exist, but no current green live proof.

Booking.com is the primary hotel path. Hotels.com is available as Expedia Group

Minimal revival order:

3. Hotels.com only after Booking.com has a current artifact baseline.
