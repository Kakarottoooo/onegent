## Codebase Patterns
- Use `git mv` (not `rm` + create) when relocating files, so history is preserved.
- NluScenario type in lib/agent/nlu-v2/types.ts is the single source of truth for supported scenarios. If a category is not in this union, its code is unreachable at runtime — safe to archive.
- All DB schema changes must use `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` (forward-compatible pattern, see lib/schema.sql).
- Booking Automation three-layer architecture (see root CLAUDE.md): programmatic nav + AI form fill + AI audit. Do not add new code to lib/booking-autopilot/ for this PRD.
- Golden tests for NLU live in lib/agent/nlu-v2/__tests__/golden-*.test.ts. They call the real extractor + router pipeline and require OPENAI_API_KEY.
- Existing golden tests (golden-solo, golden-multi, golden-trip) define expected behavior for the current scenarios — do NOT edit their expected values.
- Homepage (app/page.tsx) uses `resultCategory === "..."` string comparisons (not a `cardType ===` check) to gate per-category JSX blocks. Search for `resultCategory === "<category>"` when removing a category from the UI.
- Homepage also aggregates per-category results into `hasCategoryResults` — every new/removed category must be added/removed there too, or empty-state detection breaks.
- When archiving code with its own tests, prefer excluding `**/_archived/**` in tsconfig.json + vitest.config.ts instead of rewriting relative imports inside the archived files. Keeps history clean and avoids brittle `../../../../` paths.
- lib/agent.ts routes non-travel scenarios via `if (detectedScenario === "gift" | "fitness" | "big_purchase")` branches that call the planners in lib/agent/planners/. Archiving a planner means deleting its import AND its usage branch — typecheck will fail otherwise.
- `detectScenarioFromMessage` in lib/scenario2.ts still returns `"big_purchase"` for matching messages. After archival the branch handler is gone, so these messages just fall through to the default `parseIntent` flow. That's intentional — the NLU v2 layer (the only live NLU now) can't produce those scenarios anyway.
- `lib/__tests__/scenario2.test.ts` mixes unrelated describe blocks for multiple planners in one file. When archiving a planner referenced from there, delete its describe blocks inline rather than archiving the whole test file.
- `ParsedIntent` (lib/types.ts) is still a union of all intents including credit_card/laptop/smartphone/headphone, even after the pipelines are archived. After removing their routes in lib/agent.ts, add a guard `if (intent.category === "credit_card" | "laptop" | "smartphone" | "headphone") return buildBaseResult(intent, "restaurant");` before the restaurant fallback so TypeScript narrows to RestaurantIntent. The branch is unreachable at runtime via the NluScenario union but the type system cannot prove that on its own.
- Weekend trip flow calls `runCreditCardPipeline` in 3 places (refine-hotel, refine-flight, main). After archiving credit-card.ts, pass `creditCardRecommendations: []` to `runWeekendTripPlanner` — it handles empty via `pickCardForSpend` returning `undefined`, and `buildWeekendTripOption`'s `card` param is optional. Don't forget to also strip `creditCardRecommendations,` from the shorthand returns in `buildBaseResult` calls, otherwise a ReferenceError.
- Live travel-scoped credit-card logic that stays is `lib/agent/planners/trip-card.ts` (`getBestCardForTrip` / `buildTripCardCallout`) which uses `recommendCreditCards` from the engine directly, NOT the archived pipeline.
- Pre-existing vitest failures on this branch (as of 2026-04-24): 14 tests across `components/__tests__/RecommendationCard.test.tsx` (11), `lib/__tests__/ai-loop.test.ts` (1), `lib/__tests__/weekend-trip.test.ts` (1), `lib/__tests__/scenario2.test.ts — open-flight Google Flights URL` (1). Do NOT try to "fix" these in a positioning-shift story — they are unrelated to archival work. Verify new work by checking the delta vs this baseline, not the absolute count.
